# تلگرام و ربات «ارسال تعدیلات»

دانشجو تعدیلاتش را از **مینی‌اپ تلگرام** می‌فرستد؛ فایل مستقیم به Supabase می‌رود و
درخواست **خودکار به نویسندهٔ مربوط به همان دانشجو** می‌رسد و در **صفحهٔ «تعدیلات»**
نقش نویسنده دیده می‌شود.

---

## معماری — هیچ سروری از خودمان لازم نیست

```
┌─────────────────────────────────────────────────────────┐
│  GitHub Pages  (alkawthar.info + ArvanCloud)            │
│  tadilat-app.html · js/tadilat-app.js · css/…           │
│  ── صفحهٔ استاتیک، همان‌جایی که بقیهٔ سایت هست ──        │
└───────────────┬─────────────────────────────────────────┘
                │  باز شدن داخل تلگرام (Mini App)
                ▼
┌─────────────────────────────────────────────────────────┐
│  مرورگر دانشجو (webview تلگرام)                          │
│   ۱) نام (نوشتاری یا 🎤) · ۲) فایل‌ها · ۳) توضیحات        │
└───────────────┬─────────────────────────────────────────┘
                │  آپلود مستقیم + REST  (کلید anon، CORS تست شده)
                ▼
┌─────────────────────────────────────────────────────────┐
│  Supabase                                                │
│   tadilat_requests / tadilat_files                       │
│   Storage: student-documents/tadilat/…                   │
│   مسیریابی خودکار → assigned_agent_id                     │
└───────────────┬─────────────────────────────────────────┘
                │  Supabase JS SDK + Realtime
                ▼
┌─────────────────────────────────────────────────────────┐
│  صفحهٔ «تعدیلات» نویسنده‌ها (روی همان GitHub Pages)      │
│   تب «کارهای من» / «استخر عمومی» / «همه»                  │
└─────────────────────────────────────────────────────────┘

بوت تلگرام (اختیاری): دکمهٔ منو + دریافت فایل‌های فورواردشدهٔ واتساپ
```

### چرا Supabase سرور تلگرام نیست؟

Supabase **بک‌اند** است (دیتابیس + فایل)، نه میزبان صفحهٔ وب. صفحهٔ تلگرام یک فایل
استاتیک است و روی **همان GitHub Pages** سرو می‌شود که کل سایت روی آن است.

### چرا Telegram Serverless لازم نیست؟

Serverless تلگرام فقط برای **منطق سمت سرور** لازم است (مثل تأیید رمزنگاری‌شدهٔ
`initData`). در این طراحی هیچ بایتی از فایل‌ها از هیچ handler تلگرامی عبور نمی‌کند و
هیچ منطق سروری لازم نیست — پس هزینه و ریسک اضافه ندارد.

## مسیریابی خودکار: دانشجو → نویسندهٔ مربوطه

```
نام/شمارهٔ دانشجویی
      ↓  تطبیق نام (املاهای عربی/فارسی یکسان‌سازی می‌شوند)
profiles  (role = student)          → student_id
      ↓
orders    (تطبیق student_name یا student_id)
      ↓
orders.assigned_agent_id            → نویسنده
      ↓
tadilat_requests.assigned_agent_id  + routed_by = 'auto'
```

> ⚠️ نکتهٔ مهم دربارهٔ دادهٔ فعلی: در جدول `orders` ستون `student_id` **خالی** است و
> تنها راه تطبیق، ستون متنی `student_name` است. مسیریاب هر دو را امتحان می‌کند.
> اگر روزی `orders.student_id` پر شود، تطبیق دقیق‌تر و سریع‌تر می‌شود.

اگر دانشجو سفارشی نداشته باشد یا نامش تطبیق نخورد، درخواست **بدون نویسنده** می‌ماند
و در تب **«استخر عمومی»** صفحهٔ تعدیلات می‌افتد تا کارمند/مدیر دستی ارجاع دهد
(`routed_by = 'manual'`).

برای دیدن نتیجه روی دادهٔ واقعی:

```bat
cd telegram-bot
python bot.py --routes
```

## مسیرهای ورود تعدیلات

| مسیر | توضیح | سقف حجم |
|---|---|---|
| **تلگرام** (اصلی) | دانشجو فایل را انتخاب می‌کند → آپلود مستقیم به Supabase | **۵۰ مگابایت** |
| **فوروارد از واتساپ** | در واتساپ: Share → Telegram → همین ربات | **۲۰ مگابایت** (سقف تلگرام) |
| پوشهٔ واتساپ در تلگرام | انتخاب‌گر فایل، پوشهٔ WhatsApp را هم نشان می‌دهد | ۵۰ مگابایت |

> «اشتراک مستقیم از واتساپ به داخل تلگرام» از نظر فنی ممکن نیست (Web Share Target
> فقط برای PWA نصب‌شدهٔ اندروید کار می‌کند، نه داخل webview تلگرام). دو راه بالا
> جایگزین عملی و واقعی‌اند.

## راه‌اندازی

### ۱) جدول‌های دیتابیس (یک‌بار)

```
supabase/tadilat_telegram_migration.sql
```
را در **Supabase → SQL Editor** اجرا کنید.

### ۲) دیپلوی سایت

فایل‌های زیر باید روی `alkawthar.info` بالا بیایند (همان `git push` معمول):

```
tadilat-app.html
js/tadilat-app.js
css/tadilat-app.css
js/supabase-config.js   (از قبل هست)
```

آدرس نهایی: `https://alkawthar.info/tadilat-app.html`

### ۳) ربات

```bat
cd telegram-bot
python bot.py --init-config     :: ساخت config.json (کلید Supabase از قبل هست)
python bot.py --check           :: بررسی توکن، آدرس تلگرام، دیتابیس، جدول‌ها، Storage
python bot.py --routes          :: گزارش مسیریابی روی دادهٔ واقعی
python bot.py --set-menu        :: ثبت دکمهٔ منوی چت روی تلگرام
python bot.py                   :: اجرای ربات
```

## دستورها و سوییچ‌های ربات

| دستور | کار |
|---|---|
| `/start` | پیام خوش‌آمد + دکمهٔ «باز کردن تلگرام» |
| `/status` | پنج ارسال آخر همان کاربر + وضعیت |
| `/help` | راهنما |
| فرستادن فایل | خودکار به آخرین درخواست همان کاربر وصل می‌شود |
| `--check` | سلامت‌سنجی کامل |
| `--routes` | گزارش مسیریابی دانشجو → نویسنده |
| `--set-menu` | ثبت دکمهٔ منو بدون اجرای حلقه |
| `--init-config` | ساخت `config.json` |

## وضعیت‌ها و مراحل

```
draft → new → started → in_progress → ready → completed
                              ↘ rejected
```

| وضعیت | نمایش به دانشجو |
|---|---|
| `draft` | ناتمام (ارسال کامل نشده) — نویسنده‌ها نمی‌بینند |
| `new` | دریافت شد 📥 |
| `started` | شروع شد 🚀 |
| `in_progress` | در حال انجام ✍️ |
| `ready` | آماده تحویل 🎁 (+ `due_at`) |
| `completed` | تحویل شد ✅ |
| `rejected` | رد شد |

## نکات فنی

- فایل‌ها در باکت `student-documents` زیر `tadilat/<telegram_id>/<request_id>/…`
  ذخیره می‌شوند. نام آبجکت‌ها **ASCII** می‌شود (Storage نام فارسی را نمی‌پذیرد).
- باکت خصوصی است؛ نمایش/دانلود در سایت با **لینک موقت (signed URL)** انجام می‌شود.
- تلگرام **بدون Supabase SDK** کار می‌کند (فقط `fetch` + `XMLHttpRequest`) تا
  به CDN وابسته نباشد و نوار پیشرفت واقعی آپلود داشته باشد.
- CORS سوپابیس برای مبدأ `https://alkawthar.info` تست شده و باز است.
